\chapter{Overview and Executive Summary}\label{intro}

As noted in the article \href{https://ieeexplore.ieee.org/document/10420981}{Handwritten Character Recognition: A Comprehensive Survey}, Handwritten Character Recognition (HCR) plays a vital role in numerous domains, including document digitization, automatic text recognition, signature verification, and postal automation. Over the years, HCR has advanced significantly, driven by the growing demand for accurate, efficient recognition systems \autocite{AAASM_SICI10420981}.

\section{Project Description}\label{project-description}

\begin{noteblock}
All the source files for \emph{this Project} are available in the \emph{Project}'s \href{https://github.com/AzKurban-edX-DS/edx.capstone.choose-your-own}{GitHub repository}\autocite{edx.Capstone_CYO}.

\end{noteblock}

In this project, we will develop and explore several HCR models, based on popular ML algorithms that convert handwritten alphanumeric symbols into a digital, machine-readable form.

We will start with \href{https://soulpageit.com/ai-glossary/shallow-learning-explained/}{Shallow Learning (SL)} models, using \href{https://rafalab.dfci.harvard.edu/dsbook-part-2/ml/resampling-methods.html\#sec-knn-cv-intro}{k-Nearest Neighbors (kNN)} and \href{https://rafalab.dfci.harvard.edu/dsbook-part-2/ml/algorithms.html\#sec-random-forests}{Random Forest (RF)} methods. These models development and evaluation are described in detail below in Sections {[}k-Nearest Neighbors + Principal Component Analysis (kNN+PCA) Multiclass Classifier (MCC) Model{]} and \hyperref[random-forest-rf-mcc-model]{Random Forest (RF) MCC Model} of \emph{this Report}, respectively.

Next, we will try \href{https://soulpageit.com/ai-glossary/deep-learning-explained/}{Deep Learning (DL)} models, including \href{https://smltar.com/dldnn}{Dense Neural Network (DNN)} and, finally, \href{https://smltar.com/dlcnn\#what-are-cnns}{Convolutional Neural Network (CNN)} models, as recent research shows that DL performs better at image recognition --- the task addressed by \emph{this Project}.

A more detailed explanation of \emph{Deep Learning} versus \emph{Shallow Learning} can be found in the chapter \href{https://link.springer.com/chapter/10.1007/978-3-031-69499-8_1?status=info&saved-doi=10.1007\%2F978-3-031-69499-8_1}{Machine Learning Methods from Shallow Learning to Deep Learning} of the book \href{https://link.springer.com/book/10.1007/978-3-031-69499-8?status=info&saved-doi=10.1007\%2F978-3-031-69499-8}{Shallow Learning vs.~Deep Learning: A Practical Guide for Machine Learning Solutions} by editors Ömer Faruk Ertuğrul, Josep M. Guerrero, and Musa Yilmaz\autocite{Akinci2024}.

The \textbf{\emph{DNN-Based}} models are as follows:

\begin{itemize}
\tightlist
\item
  \textbf{\emph{DNN-Based Basic MCC Model:}} described in Section {[}Dense Neural Network-Based Basic Multiclass Classifier (DNNB MCC) Model{]};
\item
  \textbf{\emph{Tuned DNN-Based MCC Model:}} described in Section \hyperref[tuned-dnn-based-tdnn-mcc-model]{Tuned DNN-Based (TDNN) MCC Model}.
\end{itemize}

The last models we will build and explore, the \textbf{\emph{CNN-Based}} models, are as follows:

\begin{itemize}
\tightlist
\item
  \textbf{\emph{CNN-Based Basic MCC Model:}} described in Section {[}Convolutional Neural Network-Based Basic (CNNB) MCC Model{]};
\item
  \textbf{\emph{Tuned CNN-Based MCC Model:}} described in Section \hyperref[tuned-cnn-based-tcnn-mcc-model]{Tuned CNN-Based (TCNN) MCC Model}.
\end{itemize}

Finally, we will conduct a final test of the best model we have developed, using a specially designated dataset, and see what we will achieve.

\section{Running the Project}\label{running-the-project}

Once the system environment is fully configured, if you have enough time to execute all the scripts and automatically generate \emph{this report} upon their completion in a single session, the easiest approach is to run the \href{https://github.com/AzKurban-edX-DS/edx.capstone.choose-your-own/blob/main/r/support-scripts/__run-all.R}{\_\_run-all.R} script.

This script serves as a starting point for running the project execution pipeline that culminates in a \emph{PDF report}. It coordinates the process by sequentially executing two main R scripts, ensuring the script files exist, and outputs detailed execution logs to both the console and log files.

The first script it launches, \href{https://github.com/AzKurban-edX-DS/edx.capstone.choose-your-own/blob/main/r/index.R}{index.R}, is the entry point to the project's execution pipeline and the main script that runs all the other execution scripts sequentially.

However, although the \href{https://www.kaggle.com/vaibhao}{dataset author} claims that the images were transformed into 32x32-pixel grayscale images, a quick analysis of the raw data showed that at least some images have different sizes.

This functionality has been implemented in the \hyperref[appndx_b.raw_img.dat2std_bin]{raw-img.dat2std\_bin.R} support script described below in \hyperref[appndx_b]{Appendix B: Support Scripts}.

As already mentioned above in the \hyperref[downloading-preprocessing-input-datasets]{Downloading \& Preprocessing Input Datasets} section, the \emph{raw image data} undergoes preprocessing via the \hyperref[appndx_b.raw_img.dat2std_bin]{raw-img.dat2std\_bin.R} script (described below in \hyperref[appndx_b]{Appendix B}), which includes \emph{resizing the images to a uniform dimension} (\texttt{28x28} in our case) and \emph{binarizing} them.

Additionally, the images are trimmed during preprocessing to remove noninformative spatial data from their edges.

The task runs only once. By the end of execution, it caches the results in a backup file on the local disk. On follow-up calls, it first checks whether the cache exists. If found, it just shows a warning that the results have already been constructed and cached on disk.

\begin{noteblock}
Most of the scripts in \emph{this Project} follow the same pattern: they cache the results on disk upon completion and check the cache on subsequent calls. If found, they either load the results from the cache or merely show a warning message (the former is implemented in the model training scripts; the latter describes how the data processing scripts work).

\end{noteblock}

\protect\phantomsection\label{func.load_image.list.details}
\paragraph{Details}\label{details-1}

\hfill\break

Below is the \emph{step-by-step execution flow} of the function:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \textbf{File Path Discovery:} Internally invokes the \hyperref[func.img.file.get_list]{img.file.get\_list} user-defined helper function (described below in the \hyperref[appndx_aux40img_proc]{Image Processing} Section) to gather a structured list of file paths from each target subfolder, applying optional maximum limits (passed in the \hyperref[func.load_image.list.args.char_files.max]{char\_files.max} argument), random sampling (depending on the value passed in the \hyperref[func.load_image.list.args.random_sample]{random\_sample} argument), and seed generation (if the \hyperref[func.load_image.list.args.seed]{seed} argument value is not \texttt{NA}).
\item
  \textbf{Label Generation:} Extracts directory names from the file path list and converts them into a factor to serve as classification labels.
\item
  \textbf{Iterative processing of class directories:} Iterates through each directory, performing the following operations:

  \begin{enumerate}
  \def\labelenumii{\alph{enumii})}
  \tightlist
  \item
    \textbf{Batch Loading:} Calls the custom loader function (the pointer to which is passed in the \hyperref[func.load_image.list.args.fn.load_image.dat]{fn.load\_image.dat} argument) using the \href{https://www.rdocumentation.org/packages/purrr/versions/1.2.0/topics/map}{map} \texttt{R} function across all file paths in the folder.
  \item
    \textbf{Data Validation \& Filtering:} Evaluates a validity check on the loaded image data. Specifically, it checks that the binary matrix elements sum to greater than zero, effectively filtering out blank, corrupt, or unreadable images.
  \end{enumerate}
\item
  \textbf{Consistency Checks:} Enforces a safety assertion to ensure that the filtered image list length strictly matches the corresponding filtered file path list length.
\end{enumerate}

\protect\phantomsection\label{func.load_image.list.value}
\paragraph{Value}\label{value}

\hfill\break

Structured list containing two primary components:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \emph{Label list:} A factor of \emph{class labels};
\item
  \emph{Image list:} A nested list mapping each \emph{class folder} to its valid loaded \emph{image data} and corresponding \emph{file paths}.
\end{enumerate}

\protect\phantomsection\label{func.img.file.get_list.details}
\paragraph{Details}\label{details-2}

\hfill\break

This is an auxiliary function that is used internally in the \hyperref[func.load_image.list]{load\_image.list} function as shown above in the \hyperref[func.img.file.get_list.usage]{Usage} Section of \emph{this Description}.

Below is the \emph{step-by-step execution flow} of the function:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Subfolder Discovery:} If the \hyperref[func.img.file.get_list.args.folder.list]{folder.list} argument value is \texttt{NULL} (the \emph{folder list} is not provided), the function retrieves all subdirectory names inside the \emph{root directory} (using the path passed in the \hyperref[func.img.file.get_list.args.root_path]{root\_path} argument) and uses them as the \emph{folder list} for further processing. Otherwise, the \hyperref[func.img.file.get_list.args.folder.list]{folder.list} value is used.
\item
  \textbf{File Path Collection:} Next, it iterates through the \emph{folder list} determined in the previous step, constructs the \emph{full path} for each folder, and retrieves all file paths in that folder.
\item
  \textbf{Capping and Sampling:} If the value for the \hyperref[func.img.file.get_list.args.char_files.max]{char\_files.max} argument is provided and does not exceed the folder's file count, the number of files to process is limited to that value.
\end{enumerate}

\begin{noteblock}

\begin{itemize}
\tightlist
\item
  If the condition above is met, the \emph{file selection method} depends on the value of the \hyperref[func.img.file.get_list.args.random_sample]{random\_sample} argument. If it is \texttt{TRUE}, a \emph{sample} of the size provided in the \hyperref[func.img.file.get_list.args.char_files.max]{char\_files.max} argument is taken using a \emph{reproducibility seed offset} by the folder's index if a \emph{seed} is provided (the value of the \hyperref[func.img.file.get_list.args.seed]{seed} argument is not \texttt{NA}). Otherwise, a top list of the size provided in the \hyperref[func.img.file.get_list.args.char_files.max]{char\_files.max} argument is selected.
\item
  Otherwise, the full list of file paths obtained in the previous step is used for the final result.
\end{itemize}

\end{noteblock}

A \emph{named nested list} where each element represents a \emph{subfolder}, containing its \emph{root path} and the \emph{file path list}.

\paragraph{Details}\label{details-3}

\hfill\break

Below is the \emph{step-by-step execution flow} of the function:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \textbf{\emph{Image Loading:}} The function begins by reading the image file from disk into memory as an object using \href{https://docs.ropensci.org/magick/reference/editing.html}{magick::image\_read}.
\item
  \textbf{\emph{Matrix Conversion \& Validation:}} Converts the loaded image into a numeric matrix representation using the user-defined helper function \hyperref[func.magick_img2matrix]{magick\_img2matrix} described below in described below in the \hyperref[appndx_aux40img_proc]{Image Processing} Section.
\item
  \textbf{\emph{Image Validation \& Conditional Cropping:}} Evaluates the matrix's maximum value to check whether the image is entirely blank or empty. If valid content exists (the maximum pixel value is greater than zero), it applies \href{https://docs.ropensci.org/magick/reference/editing.html}{magick::image\_trim} to automatically crop out uniform background borders or whitespace, centering the content around the core visual features.
\item
  \textbf{\emph{Data Extraction:}} Finally, it extracts and returns the underlying raw pixel buffer data using the \href{https://docs.ropensci.org/magick/reference/editing.html\#details}{magick::image\_data} helper function.
\end{enumerate}

\begin{noteblock}
This is an auxiliary function, the pointer to which is passed in the \hyperref[func.load_image.list.args.fn.load_image.dat]{fn.load\_image.dat} argument to the \hyperref[func.load_image.list]{load\_image.list} function, as shown above in the \hyperref[func.load.img_trimmed.dat.usage]{Usage} Section of \emph{this Description}.

\end{noteblock}

\protect\phantomsection\label{func.magick_img2matrix.details}
\paragraph{Details}\label{details-4}

\hfill\break

Below is the \emph{step-by-step execution flow} of the function:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{\emph{Raw Binary Data Extraction:}} The function calls the {[}image\_data{]} function to extract the underlying raw hexadecimal or integer byte array buffer from the \href{https://docs.ropensci.org/magick/reference/editing.html\#details}{\emph{magick} Image object}.
\item
  \textbf{\emph{Color Channel Isolation:}} Slices the multidimensional array to isolate the primary color channel matrix. For grayscale or black-and-white pipeline images (as in our case), this captures the single intensity plane.
\item
  \textbf{\emph{Data Type Conversion:}} Explicitly casts the extracted data array elements from raw/character bytes into a numeric data type, making mathematical operations possible.
\item
  \textbf{\emph{Min-Max Normalization:}} Divides the entire matrix by 255 (the maximum 8-bit color intensity value) to normalize pixel values into a clean floating-point scale ranging from 0.0 (black/background) to 1.0
\end{enumerate}

\begin{noteblock}
This is a utility function used internally by the other user-defined functions, as shown in the usage example above in the \hyperref[func.magick_img2matrix.usage]{Usage} Section of \emph{this Description}.

\end{noteblock}
